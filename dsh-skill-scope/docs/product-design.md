# 技能开关（skill-scope）产品设计

日期：2026-10-18
状态：设计已定，实现中

## 一句话

让「哪些 skill 出现在这个会话里」变成三层开关：全局默认、工作区默认、会话临时。关掉的 skill 不进入模型目录、不占上下文；再次打开就回来；**全程不碰任何 `SKILL.md`**。

## 为什么需要它

现状是：`~/.agents/skills` 下的每个 skill 都会出现在每个会话的 `<available_skills>` 里。这台机器上 62 个 skill 的 frontmatter 合计约 2.4 万字符，全部注入进每一次会话的第一条消息。

于是出现两种互相污染的场景：
- 写 PPT 的会话里，`tdd`、`systematic-debugging`、`plugin-write` 这些编码技能挂在目录里，描述还挺长，模型每一步都在读它们。
- 写代码的会话里，`ppt-master`、`ppt-design-dna`、`icbc-report-deck` 这些也是一样。

现有两条杠杆都不合适：
1. **技能中心**（`@linxin666/dsh-client-ui-skill-explorer`）改的是 `SKILL.md` 里的 `disable-model-invocation`，也就是一个永久、全局的状态。你在 PPT 会话里关掉 `tdd`，回到代码仓库它还是关的。
2. **agent preset** 换的是整份组合，粒度是「换一套能力」，不是「今天这个不要」。

真正缺的是一层**按会话求值的过滤**，而且这一层不能改磁盘上的东西。

## 用户与场景

单人使用，同一个用户在多个工作区之间来回切。典型一天：

- 上午在 `/Users/zhongqing/Software/某项目`（有 `.git`）写代码。
- 下午在 `Personal/写PPT` 目录做汇报材料。
- 中途在任意会话里临时想用一下某个 skill。

## 产品行为

### 三层开关

| 层 | 存在哪 | 影响谁 | 什么时候写 |
|---|---|---|---|
| 全局默认 | 设置页 →「技能开关」 | 所有工作区、所有会话 | 用户手动 |
| 工作区默认 | 会话顶部 workspace 名字旁 | 该目录（含子目录）下所有会话 | 用户手动，持久化 |
| 会话临时 | 输入框左侧那个药丸（Continue 旁边同一排） | 当前会话 | 用户手动，不持久 |

**解析规则：就近覆盖。** 会话 > 工作区 > 全局；某一层没提到的 skill，继承上一层；哪一层都没提到，默认**显示**。

也就是说装上插件本身不改变任何东西——所有 skill 照旧可见，直到你第一次拨开关。

> 关于「下层能不能关掉上层开的」：**能**。这是我们讨论后选的方案。理由是「只能加不能减」在真实场景下会退化——全局默认如果包含 `office`，你在代码仓库里关不掉它，只能去全局删，而删了 PPT 那边也没了。为了让「只能加」成立，全局默认会被迫缩成所有工作区的交集，每个工作区再重新开一大半，反而更累。
>
> 覆盖制的代价是「我记得它开着，怎么不见了」。这个用两件事抵消：面板里每个 skill 都标出**当前是哪一层做的决定**（默认 / 全局 / 工作区 / 会话），一眼看见是谁关的；以及技术上不做锁（讨论后决定不要，保持简单）。

### 「关掉」到底关掉了什么

关掉 = **对模型隐藏**，不是加锁、不是改文件、不是禁用。

- 从 `<available_skills>` 里消失，模型看不到它、也调不动它（内置 `skill` 工具会明确回「not available for model invocation」）。
- **人仍然可以用**：在输入框打 `/skill-name` 仍然能触发，`/` 菜单里仍然看得到（带「仅用户可调用」标记）。这是刻意的——开关是给上下文减负的，不是给用户设限的。
- 磁盘上什么都不变。

### 「打开」的两级

讨论里定的是这个：

- **拨开关打开** → 回到目录。模型知道有这个东西，真要用时自己读。
- **点「立即加载」** → 把正文塞进下一步的上下文。省去「模型先知道、再读一次」的往返。

「立即加载」的实现有个行为要知道：它把正文排进会话下一步的收件箱，`agent.inject()` 按设计**不会唤醒**空闲的 agent。所以点了之后需要在会话里任意发一句话，正文才会随那一步进上下文。界面上会提示「已排入下一步」。

### 界面位置

| 位置 | 内容 |
|---|---|
| 输入框左侧（Continue 那几个开关同一排） | 药丸：`技能 58/62`，点开是面板，默认停在**本会话**页 |
| 会话顶部 workspace 名字旁 | 工作区默认入口，点开面板停在**本工作区**页 |
| 设置页新增一页「技能开关」 | 全局默认，列出全部 skill |

面板三个 tab：本会话 / 本工作区 / 全局默认。顶部一句话说明当前层影响谁。每行： skill 名、来源徽章（谁决定的）、两行描述、右侧开关。搜索框按名称和描述过滤。底部「本层恢复默认」把这一层的覆盖清空，回到继承。

### 工作区怎么识别

按目录路径，取**最近的含 `.git` 的祖先**；没有 `.git` 就用自己的路径。这跟 DSH 自己找项目根的逻辑一致，所以 `Personal/某项目/src` 里开的会话和 `Personal/某项目` 里开的会话共享同一套工作区开关。

### 生效时机

**下一步就生效，不用重开会话。** 因为 skill 目录本来就是每步重算的；拨完开关，内置的目录消息会检测到条目变化并自动发布替换目录。

## 非目标

- 不做 skill 的增删改查（那是技能中心的事）。
- 不做「按任务类型自动判断该开哪些」（没有可靠的判据，容易自作聪明）。
- 不改 `SKILL.md`，任何时候都不。
- 不做锁 / 强制层（讨论后明确不要）。
- 不做跨机器同步（状态就是一个本地 JSON 文件）。

## 已知取舍

- **会话层不持久化。** 重开会话回到工作区默认。这是有意的：会话级调整是「今天这一次」的意思，留着反而会让下一天莫名其妙少几个 skill。
- **状态是进程内缓存 + 文件。** 每步读一次文件（几 KB），换来「手工改文件也能立刻生效」。
- **工作区键是绝对路径。** 目录改名或搬家，那套工作区开关就失配了（旧键留在文件里，不影响使用，只是成为孤儿）。

## 验收标准

1. 全新安装、不做任何设置：模型看到的目录跟不装插件完全一致。
2. 在某个会话里关掉 `office`：下一步该会话的 `<available_skills>` 里就没有 `office`；同一时刻另一个会话里 `office` 仍在。
3. 把 `office` 设成全局关、在工作区 A 打开：工作区 A 的新会话看到 `office`，其他工作区看不到。
4. 关掉的 skill 用 `/office` 仍能在 UI 菜单里选到并触发。
5. 点「立即加载」，发一句话，正文出现在上下文里。
6. 任何操作之后 `~/.agents/skills/**/SKILL.md` 的 mtime 都不变。
